Website · Design language

realfast Website Design Language

An additive extension to the core realfast editorial design system, dedicated to the marketing website (About, People & Culture, Security, and future long-scroll pages). The core system stays authoritative for print/templates; this layer defines how that look behaves on a dark-punctuated, animated, full-bleed scrolling web page.

Everything here is additive — the core rules still hold: name always lowercase + italic (realfast), single spaced hyphens (no em-dashes), US spelling if consistent, no emoji, one red accent used sparingly, plain-spoken and specific voice.

01 · In one line

The website look in one line

An editorial newspaper that scrolls like a story. Warm paper and cream sections alternate down the page, punctuated by a few deliberately premium near-black bands. Serif headlines carry gradient-filled accent words. Everything arrives on scroll with restrained motion. No boxes, no divider lines — sections flow into one another on soft shadow alone.

  • Dark bands are never flat black. They always carry a layered gradient + red glow + hairline highlight (§4).
  • Sections never touch with a hard line. Continuity comes from a soft shadow the band casts onto the next, not a border or <hr>.
  • Accent words are gradient-filled, not flat color (§3).

03 · Gradient words

Gradient accent words (signature)

The website's single most recognizable device. Key words inside serif headlines on dark bands are gradient-filled via background-clip:text instead of a flat color.

/* red accent words: "metric", "shipped", "AI", "honest", "safe" */
background: linear-gradient(100deg, #ffb3ae 0%, var(--rf-red-400) 55%, #c00d07 100%);
-webkit-background-clip: text; background-clip: text; color: transparent;

/* white accent words: "features", "humans", "architects" */
background: linear-gradient(100deg, #ffffff 15%, #d8d3c8 85%);
-webkit-background-clip: text; background-clip: text; color: transparent;

/* mission / closing phrase (longer, warmer sweep) */
background: linear-gradient(100deg, #f0554f 0%, #E3120B 45%, #a30b06 100%);
  • Use only on 1-2 words per headline — the contrast pair (AI vs humans, features vs metric). Never gradient a whole line.
  • On italic words add padding-right:.05em so the clip doesn't crop the terminal stroke.
  • Base headline color stays dim white (rgba(255,255,255,.66)) so the gradient words pop.
  • The pattern encodes meaning: red = machine/AI, white = human judgment. Keep that mapping consistent.
04 · Dark bands

Premium dark bands

Dark sections (hero, final CTA, the occasional ink chapter) are never flat background:#111. They stack:

background:
  radial-gradient(ellipse 85% 65% at 50% -12%, rgba(227,18,11,.22), transparent 62%),  /* red glow, top */
  radial-gradient(ellipse 60% 45% at 85% 110%, rgba(227,18,11,.08), transparent 65%),  /* faint 2nd glow */
  linear-gradient(180deg, #1d1c1a 0%, #121211 55%, #0c0c0b 100%);                       /* charcoal grad */
box-shadow:
  inset 0 1px 0 rgba(255,255,255,.07),        /* hairline top highlight */
  inset 0 -40px 80px rgba(0,0,0,.35);         /* soft bottom vignette */
  • Hero: glow radiates from the top edge (entering the page).
  • Final CTA band: glow rises from the bottom behind the buttons; gradient runs dark-to-warm downward; starts from #050505.
  • Inline ink chapter: milder — glow .16, gradient #1c1b1a → #0e0e0d, plus a faint light border so it reads as an elevated dark card within light surroundings.

The intent: depth and warmth, so dark bands feel like premium print stock, not a PowerPoint black slide.

05 · Section flow

Seamless section flow (no rules, no boxes)

Full-bleed sections stack edge to edge. Never separate them with a border, <hr>, or a floating card with margins. Continuity is a soft shadow each band casts onto the next:

/* light band */
box-shadow: 0 24px 40px -32px rgba(17,17,17,.14);
position: relative; z-index: 1;

/* inset variant (shadow reads at top of receiving band) */
box-shadow: inset 0 28px 32px -30px rgba(17,17,17,.18);   /* ink band: rgba(0,0,0,.55) */

Chapters are full-bleed alternating white/cream — not rounded cards. Content cards inside a section still exist (§6), but the section shells themselves do not. Rubrics get no hairline rule beside them.

06 · Cards

Cards (the "premium" content-card system)

For content blocks within a light section (principle cards, strip cards, panels):

border: 4px solid #fff;
background: linear-gradient(165deg, #ffffff 0%, var(--surface-raised) 60%);  /* not flat cream */
border-radius: 24px;  /* 20px mobile · 12px tiles · 999px pills */
box-shadow: 0 6px 18px rgba(17,17,17,.08), 0 20px 44px rgba(17,17,17,.1);   /* tight + ambient */
transition: transform .35s ease, box-shadow .35s ease;
  • Hover: lift translateY(-3px), shadow deepens.
  • Padding: roomy — desktop ~36-44px sides / 40-48px bottom; mobile ~34px 30px 38px. Cards must breathe.
  • No internal seams: an illustration container inside a card has no background of its own and no divider between image and text.
  • Portrait/photo cards: 4px white border + layered shadow, B&W at rest → color on hover, lift -5px.
07 · Icons

Iconography

Core system uses Tabler outline; the website adds a premium icon-chip treatment for repeated icon buttons (social/profile links, feature chips):

/* 34px desktop · 40px mobile circle */
background: linear-gradient(145deg, #ffffff, var(--surface-raised));
border: 1px solid var(--border);
box-shadow: inset 0 1px 0 rgba(255,255,255,.9), 0 2px 6px rgba(17,17,17,.06);
color: #57534A;  /* warm-grey glyph at rest — NOT red */
  • Hover: red border + red glyph + red-tinted shadow + -1px lift.
  • Feature/section icons: 56px gradient chips, hairline ring + inner highlight, finer 1.75px strokes in deep warm ink, duotone soft fills inside closed shapes.
  • Red is reserved — icons rest in warm grey, red only on hover or for CTAs/rubrics.
  • Filled Bootstrap-style 13px glyphs are OK inside small profile chips (LinkedIn / GitHub / RSS) where a filled set reads better at tiny sizes.
08 · Type

Typography (website scale)

Core faces unchanged — Source Serif 4 (headlines/body/quotes), IBM Plex Sans Condensed (labels/rubrics), monospace (counts/figures).

Rubrics / kickers are SENTENCE CASE. No text-transform:uppercase, no letterspacing. Bold, red, sans — e.g. "About realfast", "Our mission", "The model", "Join us". They stand out by weight and color, not by shouting. (Exception: tiny meta rows like a city-name strip may stay small uppercase.)

09 · Motion

Motion

Restrained, editorial, one-shot. Decorative motion cheapens the tone.

  • Scroll reveal: IntersectionObserver, threshold ~0.08-0.1, fade-up 14-16px, 550-600ms cubic-bezier(.22,.61,.36,1), fires once. Re-observe rows rendered after filter/accordion changes.
  • Cards: rise with a subtle scale-in (translateY(30px) scale(.97) → none).
  • Directional sweep (desktop): alternating chapters slide in from opposite sides (translateX(±56px)).
  • Hero "beats": line 1, then line 2 (~240ms later), then scroll cue (~400ms), each a fade-up. Scroll cue bounces gently.
  • Draws: accent underline draws left→right on section entry.
  • Secondary content: fades in ~400ms after the primary body so the eye lands on the headline first.
  • Failsafe: only force-reveal everything if the observer never fired (~3s with zero .is-in). Do NOT blanket-reveal on a timer — it kills the scroll animations.
  • Wrap all motion in @media (prefers-reduced-motion: reduce) and disable transforms there.
  • No parallax, no Ken Burns on faces, no auto-playing carousels of people — dignity over spectacle.
10 · CTAs

CTAs

  • Primary: red-fill pill (--rf-red-500), 999px radius, ~17px 32px padding, white text.
  • Secondary: ghost pill — transparent, 1px border at 65% white on dark bands (must read clearly, not barely-there), fills to solid white on hover. Identical height/padding/radius to primary so they read as a set.
  • No arrows on CTA buttons. A hover micro-lift/glow is the affordance.
  • Hover: soft red glow (0 8px 32px rgba(227,18,11,.35)) on the primary; both may rise-in with a slight stagger.
  • Mobile: buttons stack full-width.
  • Real destinations: careers → /careers, apply → join.realfast.ai, contact → /contact, people → /people.
11 · Spine

Long-scroll page anatomy (the "spine")

The About page established a reusable structure for narrative pages:

  • Site nav (existing header component).
  • Premium ink hero — sentence-case kicker, big serif headline with gradient contrast words, two-beat entrance, scroll cue. Optional dim rail numeral ("00").
  • Mission / standfirst band (cream, centered, no rules) — one bold idea, closing phrase in the red gradient.
  • Numbered chapters — full-bleed alternating white/cream, seamless shadow flow. Desktop: 170px | 1fr grid with a sticky left rail (44px serif numeral + sentence-case bold label). The active chapter's numeral turns red and scales ~1.08 as it enters; one chapter may be a premium ink band.
  • CTA band (premium black gradient) — contrast-word headline, two pills, no arrows.
  • Footer (existing component).

Explicitly not part of the pattern: no sticky utility/label bar, no scroll-progress line — both add chrome without helping the narrative. Active-chapter logic: active = last chapter whose top ≤ 45% of viewport and bottom > 25%.

12 · Roster

Directory / roster pattern (People page)

  • Filter chips (inline row, not a dropdown): All · Leadership · GTM and AI Transformation · Engineering · Salesforce · Program Management · Lead Forward Deployed Engineers · Forward Deployed Engineers. Full-length names, no abbreviations. Active chip = ink fill + white text; labels never wrap. Mono "N people" count below. No search field.
  • Department accordions: sentence-case bold header (15px / 14px mobile) + red mono count + chevron (rotates 180° open), 1px hairline. Leadership open by default; selecting a chip auto-opens that department. Roles spelled out in full.
  • Person row: B&W photo → color on hover, name, role, then premium icon chips (§7) linking blog-author / LinkedIn / GitHub (hidden if none).
  • Photos: subtle B&W/duotone at rest; normalize crops so eyes sit on a consistent line (background-position tuned per person).
13 · Imagery

Imagery

  • Core signature (muted risograph spot illustration on cream) still applies for editorial/illustrative slots.
  • The website adds B&W / duotone photography for people (warm, low-contrast, not glossy) and a 3D render slot for the map/locations moment (16:9 desktop / 16:10 mobile, 12-14px radius). If a diorama video is supplied use <video muted loop autoplay playsinline>; otherwise ship the still.
  • Investor / partner logos render in ink on light (export ink versions; don't rely on a CSS brightness(0) filter in production).
14 · Case-study index

Case-study index / listing (the "gallery of proof")

Built on the same editorial rf-cs surface as the detail pages, so the listing flows continuously into them. Top to bottom: editorial masthead → full-width hero → featured lead card → uniform card grid → a single closing dark band.

Masthead — de-templated (anti-AI-tell)

  • Sentence-case red kicker left, quiet meta figure right.
  • No full-width connecting hairline rule between kicker and figure.
  • Meta count set in the sans, not monospace.

Hero — use the full width

  • Serif headline runs the full container width (1-2 lines). Do not cap it with a narrow max-width that forces extra wraps.
  • One gradient accent word only; full-width standfirst.

Editorial card (variant of the §6 premium card, for the newspaper surface)

  • Fill linear-gradient(165deg, #fff → cream); soft layered shadow; hover lift.
  • No thick 4px white mat border; radius 2px (not 24px) — a crisp lifted surface, not a chunky rounded box.
  • Sentence-case red rubric; serif title turns red on hover; a two-metric row with the lead metric in red.

Card CTA affordance (reusable rule)

  • The whole card is the link — the "Read case study" label is a styled <span>, never a nested <button> (redundant, and invalid inside an anchor).
  • Styled as a red ghost pill that fills red on card hover — clearly a CTA, no arrow.
  • No arrow-text links ("Read more →"); use a specific label ("Read case study") over generic "Learn more".

Closing band + footer

  • A single premium dark band (§4) with a gradient contrast word and the matched red / ghost pill set (§10); headline 2 lines, standfirst tightened.
  • Engineering note: any page on the case-study surface must carry the footer.is-light rules (now in case-study-editorial.css) or the white footer nav renders invisible.
15 · Recap

Do / Don't recap

Do

  • Flat paper + cream rhythm, premium dark punctuation.
  • Gradient contrast words, sentence-case red rubrics.
  • Seamless shadow flow between sections.
  • Layered card shadows + hover lift, roomy padding.
  • Warm-grey icons at rest, red on hover.
  • One-shot scroll reveals, reduced-motion safe.

Don't

  • Flat black bands, hard divider lines, floating bordered section cards.
  • All-caps letterspaced rubrics, arrows on CTAs, barely-there ghost borders.
  • Blanket timer-reveal (kills scroll motion), parallax/Ken Burns on faces.
  • Red on resting icons, more than 1-2 gradient words per headline.
  • Any color outside the brand + illustration token set.
